# Unit Tour — 외부 공유용 빌드

원본 핸드오프 번들(`../Unit Tour (standalone).html`, 25.9MB)에 파노라마 15장을 인라인하고
전체 용량을 Artifact 게시 한도(16MB) 안으로 재패키징한 결과물.

## 공유 링크

Artifact: https://claude.ai/code/artifact/ca4a818e-6ea5-46df-8caf-4effd6411714
(기본은 비공개. 페이지 공유 메뉴에서 링크 공개로 전환해야 외부에서 열림)

## 파일

- `Unit_Tour_standalone.html` — 단독 실행본. 브라우저로 바로 열면 동작 (11.1MB)
- `artifact-body.html` — Artifact 게시용. 외곽 `<html>/<head>/<body>` 태그를 제거한 본문 조각
- `pano-webp/` — 번들에 인라인한 파노라마 WebP 원본
- `0.jpg`~`14.jpg`, `t0.jpg`~`t14.jpg` — 업로드된 파노라마·썸네일 원본(JPEG)

번들 부트스트랩이 실행 시 document 전체를 교체하는 구조라, 조각 형태로 감싸져도 동일하게 렌더링된다.

## 원본 대비 변경점

에셋만 재인코딩했고 UI·레이아웃·로직·폰트는 원본 그대로다.

| 에셋 | 원본 | 변경 후 |
|---|---|---|
| 평면도 (5000×4500 PNG) | 15.0MB | WebP 3000×2700 q90 — 466KB |
| 입체 평면 (1857×1011 JPEG) | 350KB | WebP q86 — 41KB |
| 미니맵 (698×405 PNG) | 126KB | WebP q88 — 35KB |
| 파노라마 15장 (4096×2048 JPEG) | 6.9MB, 번들 미포함 | WebP q86 — 3.8MB, 번들 인라인 |

전체 25.9MB → 11.1MB.

파노라마는 해상도를 4096×2048 그대로 유지했다. 뷰어 FOV가 약 89°라 화면 폭의 약 1/4만
표시되므로, 모바일 뷰포트에서도 4096 미만으로 줄이면 눈에 띄게 흐려진다.

## 파노라마 연결 방식

원본은 `rooms` getter가 `pano/{id}.jpg` 상대 경로를 참조했는데, 번들에는 해당 파일이
없어 WebGL 폴백 단색만 나왔다. 다음 두 곳을 고쳐 매니페스트 uuid를 직접 물리게 했다.

```js
const PANO = [ /* 공간 0~14 순서의 매니페스트 uuid 15개 */ ];
get rooms() { return ROOMS.map(r => ({ ...r, thumb: PANO[r.id], src: PANO[r.id] })); }
```

부트스트랩이 템플릿 문자열 전체에 대해 `template.split(uuid).join(blobUrl)` 치환을 돌리므로,
JS 리터럴 안의 uuid도 그대로 blob URL로 바뀐다. 썸네일(`t0`~`t14`)은 현 디자인에서
쓰이지 않아 번들에 넣지 않았고, `thumb`도 같은 uuid를 가리키게 두었다.

## 남은 제약

- **타입 전환은 라벨만 바뀐다.** 59A~84C 7종 모두 파노라마·도면 세트가 따로 필요한데
  현재는 84A 한 세트뿐이다. 7종 전부(105장)를 붙이면 16MB 한도를 넘으므로,
  그 단계에서는 Artifact가 아니라 정식 웹호스팅으로 옮겨야 한다.
- **DP는 톤 오버레이로 임시 표현.** 실제로는 DP 적용 파노라마 세트를 별도 로드해야 한다.
- **평면 오버레이는 84C 도면, 미니맵은 별도 샘플 도면.** 실서비스에서는 선택 타입과
  동일한 도면으로 통일해야 한다.
- 초기 시선(yaw)이 거실만 지정돼 있고, WebGL 컨텍스트 손실 복구 핸들러는 미구현이다.
